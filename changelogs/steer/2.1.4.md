## Что нового в 2.1.4

🛠 **steer 2.1.4** — ядро вдвое легче на флеше, правила идут по порядку спеки, выход не застревает выключенным 👇

### 📦 РАЗМЕР
✅ Пакет ядра меньше на треть: `steer-core` для mipsel_24kc — 1,8 МБ вместо 2,5 МБ, для aarch64_cortex-a53 — 1,7 МБ вместо 2,4 МБ  
✅ Ядро со всеми протоколами занимает на флеше 3,9 МБ вместо 7,2 МБ (mipsel_24kc) и 3,2 МБ вместо 5,6 МБ (aarch64_cortex-a53): wolfSSL и QUIC (ngtcp2) лежат одной копией у ядра, а не второй — внутри плагина `net1` (`net1` 1.5.0 — 0,4 МБ вместо 1,5 МБ)  
✅ Архивы плагинов из пакета ядра удаляются с флеша, как только плагин поставлен: раньше они оставались рядом с распакованными плагинами  
✅ Удаление пакета ядра убирает и плагины, которые ставил менеджер плагинов; спека, подписки и настройки в /etc/steer остаются  
✅ Код, по которому идёт трафик (шифры, туннели, транспорты, резолвер), собирается на скорость, остальное — на размер  

### 🐞 ИСПРАВЛЕНИЯ
✅ Правила применяются в порядке спеки, когда их списки пересекаются: правила одного выхода сливались в один набор на месте первого из них, и адрес из списка, который стоял ниже, мог уйти в чужой выход — например, при правилах «Instagram → A, YouTube → B, Google → A» youtube.com уходил в A. Теперь первое подходящее правило выигрывает и в правилах nftables, и в DNS; имена наборов у таких правил получают хвост `_s2`, `_s3`…  
✅ Выход с закреплённым узлом (`nodes: [N]`), чей узел перестал отвечать, называет причину в `steer status` (`node_down`) и проверяется сторожем: раньше он стоял в отказе молча, и панели, которые судят по `node_down`, перезапускали службу по кругу  
✅ Выход туннеля больше не остаётся выключенным при живом узле: ядро могло получить «узел не отвечает» позже, чем «отвечает», и держало выход в отказе до следующей смены узла; удачная проверка узла теперь снимает такой отказ  
✅ Узлы hysteria2 из подписки в формате конфигов Xray (как её получает Happ) называются по имени узла, а не все «proxy»  
✅ mipsel: копирование данных в ядре и плагинах шло побайтовым циклом сборщика вместо копирования musl — теперь musl  

### 🔧 ИЗМЕНЕНО
▫️ Плагины, связанные с библиотеками ядра (`net1` 1.5.0, `tgws`), объявляют новую ось совместимости `steer-crypto`; ядро называет свою в `steer version --json`. Ядро 2.1.3 и старше такие версии не ставит и остаётся на `net1` 1.4. Откат ядра на 2.1.3 после 2.1.4 — вместе с `steer plugin install net1 1.4.3`  


## Установка

Ядро маршрутизации по политикам для OpenWrt.

**Какой пакет брать.** Пакет один — `steer-core-*` с архитектурой в имени (та же, что показывает
`apk --print-arch` на роутере): ядро, библиотеки, менеджер плагинов, ключи официального
репозитория и семя — подписанные плагины протоколов под эту архитектуру. Протоколы (vless,
hysteria2, trojan/shadowsocks/socks/http/vmess, xsteer, obfs, WARP) — плагины `.s2p` официального
репозитория splify2: при установке ядро ставит их само из сети, а без сети — из семени. Прежние
пакеты `steer-vless`, `steer-hysteria2`, `steer-proxy`, `steer-xsteer`, `steer-obfs`,
`steer-tgws`, `steer-warpbox` и `steer-extended` пакет ядра заменяет и снимает в той же
транзакции, а выходы, которые на них стояли, получают плагины.

sing-box для podkop и forkop — плагин `box-connector` и пакет-заглушка `steer-box-connector`
из выпусков [steer-box-connector](https://github.com/splify2/steer-box-connector/releases).

**Два формата.** `.apk` — для OpenWrt 25.12 и новее, `.ipk` — для 24.10, 23.05
и всего, что осталось на opkg. Содержимое одинаковое, отличаются только
метаданные пакета.

```sh
# OpenWrt 25.12+
apk add --allow-untrusted ./steer-core-2.1.4-1_<arch>.apk
# OpenWrt 24.10 и старше
opkg install ./steer-core_2.1.4-1_<arch>.ipk
```

**`steer-obfs-*.tar.gz` — серверная половина обфускации, для VPS.** Нужна
только выходу с `obfs`: она принимает поддельный TCP снаружи и отдаёт
датаграммы локальному WireGuard. Компилятор на сервере не нужен: бинарник в
архиве статический — программа плагина `obfs`, та же, что на роутере.

```sh
tar xzf steer-obfs-2.1.4-x86_64.tar.gz
cd obfs-x86_64 && sudo sh install.sh --port 4567 --forward 127.0.0.1:51820
```

**`steer-hub-*.tar.gz` — хаб звезды xsteer, для VPS.** Отдельная половина от
obfs: здесь свой протокол (поддельный TCP с обликом TLS) и своя подкоманда
`xsteer-hub`, которой в сборке для роутера нет. Имя архива без версии —
установщик тянет его по фиксированному пути. Внутри бинарник, установщик и
справка; распаковал и запустил, ключи хаб делает сам.

```sh
tar xzf steer-hub-x86_64.tar.gz && sudo sh xs_install.sh
```
