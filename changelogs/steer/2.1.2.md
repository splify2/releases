## Что нового в 2.1.2

🛠 **steer 2.1.2** — группа из туннелей снова несёт TCP, правила применяются на OpenWrt 23.05, страна выхода определяется 👇

### 🐞 ИСПРАВЛЕНИЯ
✅ Группа из туннелей VLESS, hysteria2 или прокси, записанная в спеке раньше своих членов, вела TCP клиентов в порт, который никто не слушает: сайты через такую группу не открывались («Could not connect»), перезапуск не помогал. Теперь соединения группы идут к туннелю того члена, на котором она стоит, в каком бы порядке выходы ни были записаны  
✅ Страна выхода туннеля (`geo_cc` в `steer status`) определяется: проверка шла через устройство туннеля, а TCP через него в 2.1 не несётся — в статусе всегда стояло `geo_failed`, в журнале после каждого подъёма оставались «страна выхода не определилась» и «TCP пришёл в устройство — сброс». Теперь проверка идёт тем же путём, что трафик клиентов (плагин `net1` 1.4.2)  
✅ Процесс туннеля больше не показывает в `top` около гигабайта виртуальной памяти (VSZ 932m на роутере с 256 МБ): место под таблицу соединений он резервировал под миллион соединений на поток. Памяти резерв не занимал, но выглядел как утечка; теперь он считается от оперативной памяти роутера (256 МБ — 8192 соединения на поток)  
✅ OpenWrt 23.05: набор правил со спекой, где есть группа выходов или туннель VLESS, hysteria2, прокси, не применялся вовсе («nft отверг набор правил, прежний остаётся») — nftables 1.0.8 не принимал две записи ядра 2.1. Теперь набор пишется так, что его принимают и старые, и новые nftables  
✅ После обновления пакета ядра плагины протоколов обновляются сразу, а не в ближайшее ночное окно: исправления, вышедшие в плагинах, приходят вместе с ядром  



## Установка

Ядро маршрутизации по политикам для OpenWrt.

**Какой пакет брать.** Пакет один — `steer-core-*` с архитектурой в имени (та же, что показывает
`apk --print-arch` на роутере): ядро, библиотеки, менеджер плагинов, ключи официального
репозитория и семя — подписанные плагины протоколов под эту архитектуру. Протоколы (vless,
hysteria2, trojan/shadowsocks/socks/http/vmess, xsteer, obfs, WARP) — плагины `.s2p` официального
репозитория splify2: при установке ядро ставит их само из сети, а без сети — из семени. Прежние
пакеты `steer-vless`, `steer-hysteria2`, `steer-proxy`, `steer-xsteer`, `steer-obfs`,
`steer-tgws`, `steer-warpbox` и `steer-extended` пакет ядра заменяет и снимает в той же
транзакции, а выходы, которые на них стояли, получают плагины.

sing-box для podkop и forkop — плагин `box-connector` и пакет-заглушка `steer-box-connector`
из выпусков [steer-box-connector](https://github.com/splify2/steer-box-connector/releases).

**Два формата.** `.apk` — для OpenWrt 25.12 и новее, `.ipk` — для 24.10, 23.05
и всего, что осталось на opkg. Содержимое одинаковое, отличаются только
метаданные пакета.

```sh
# OpenWrt 25.12+
apk add --allow-untrusted ./steer-core-2.1.2-1_<arch>.apk
# OpenWrt 24.10 и старше
opkg install ./steer-core_2.1.2-1_<arch>.ipk
```

**`steer-obfs-*.tar.gz` — серверная половина обфускации, для VPS.** Нужна
только выходу с `obfs`: она принимает поддельный TCP снаружи и отдаёт
датаграммы локальному WireGuard. Компилятор на сервере не нужен: бинарник в
архиве статический — программа плагина `obfs`, та же, что на роутере.

```sh
tar xzf steer-obfs-2.1.2-x86_64.tar.gz
cd obfs-x86_64 && sudo sh install.sh --port 4567 --forward 127.0.0.1:51820
```

**`steer-hub-*.tar.gz` — хаб звезды xsteer, для VPS.** Отдельная половина от
obfs: здесь свой протокол (поддельный TCP с обликом TLS) и своя подкоманда
`xsteer-hub`, которой в сборке для роутера нет. Имя архива без версии —
установщик тянет его по фиксированному пути. Внутри бинарник, установщик и
справка; распаковал и запустил, ключи хаб делает сам.

```sh
tar xzf steer-hub-x86_64.tar.gz && sudo sh xs_install.sh
```
