## Что нового в 2.1.0

🛠 **steer 2.1.0** — протоколы стали плагинами, IPv6 через туннели и WARP, сторож и перезапуск больше не рвут живые соединения, DNS и fake-IP устойчивее 👇

### 🐞 ИСПРАВЛЕНИЯ
✅ Перезапуск службы (`/etc/init.d/steer restart`, его же зовёт обновление пакета) больше не снимает правила: трафик выходов с `on_fail: drop` не уходит мимо туннеля, а резолвер продолжает отвечать и достаётся новому демону; `stop` правила по-прежнему снимает  
✅ Неудавшееся применение спеки при старте повторяется само — через 5 с, с удвоением паузы до 5 минут; сторож считает «ядро steer включено, спека есть, набора правил нет» расхождением и ставит набор  
✅ Отвергнутый набор правил остаётся для разбора одним файлом `steer-ruleset.rejected`, а не новым файлом в памяти роутера на каждую попытку  
✅ Применение спеки больше не отбрасывает на миг трафик выхода, уже пущенного мимо туннеля (`on_fail: direct` или `zapret`)  
✅ Испорченная адресная строка списка (`300.1.1.1`, `10.0.0.0/33`, `1.2.3.4/`, `1...2`, оборванная загрузка, диапазон задом наперёд) пропускается с одним предупреждением на список, а не отвергает весь набор правил  
✅ Событие сети во время прохода сторожа (вернулся WAN) больше не теряется: выход возвращается через 5 с после прохода, а не через период  
✅ Пул адресов fake-IP больше не кончается на долгоживущем устройстве: адреса имён, которых давно не спрашивали и к которым нет соединений, возвращаются  
✅ Пакет к поддельному адресу fake-IP больше не уходит в mesh-VPN (Tailscale) и не зацикливается через него  
✅ DNS по QUIC: соединение с сервером держится с PING раз в 15 с, мёртвое закрывается до вопроса клиента — первый вопрос после простоя не ждёт полторы секунды  
✅ DoT, DoH и DNS по TCP: вопрос, ушедший в соединение с пропавшим путём, через полторы секунды повторяется на новом соединении, а не получает отказ через четыре; простаивающее соединение проверяет ядро Linux  
✅ Группа DNS-серверов `failover`: если с первым сервером нет готового соединения, следующий спрашивается через 350 мс, а не через 1,5 с; сервер, вернувшийся после паузы, проверяется вместе со следующим, и клиент проверку не ждёт; пачка вопросов, отказанных одним сбоем, удлиняет паузу сервера один раз  
✅ Группа DNS-серверов `race`: при отказе серверов группа уходит на паузу, а поздний ответ больше не снимает отказ  
✅ Собственный трафик steer больше не проходит через общий zapret  
✅ Снятие правил удаляет только правила своей пары метки и таблицы: метка, перешедшая к другому выходу, больше не уводит его трафик в чужую таблицу  
✅ Выходы с длинными именами, начинающимися одинаково, больше не сливаются в один набор правил  
✅ `status` и `diag` больше не пишут «нет NAT» у выхода, чья подмена стоит в чужой таблице с именем на «steer» (например, `steerbox`)  
✅ Предупреждение «у LAN только ULA» появляется только при правиле «только IPv6», а не у всех без IPv6 в интернет  
✅ `rm-file` больше не удаляет файл, на который ссылается спека, записанная в YAML  
✅ Подписка, которую панель отдаёт в gzip без просьбы, распаковывается — раньше выходило ноль узлов  
✅ Подписка VLESS в формате Clash YAML или sing-box JSON больше не теряет узлы (из пяти узлов брался один)  
✅ Подписки и ссылки: длинное значение узла (путь, ECH, отпечатки, конфиг vmess) больше не обрезается молча — оно берётся целиком, а не влезшее поле называется в отказе  
✅ Набор `.srs` с корнем больше 512 меток больше не отвергается как «не разобран»  
✅ Крупные датаграммы UDP: VLESS отправляет до 65507 байт (было около 14,8 КБ — дальше сессия рвалась), trojan, Shadowsocks, SOCKS5 и vmess — до предела своего формата, а не 4 КБ; hysteria2 собирает перемешанные куски двух датаграмм и куски длиннее 1400 байт  
✅ VLESS: ответ узла, чей заголовок пришёл по частям, больше не ломает соединение; короткий ответ сервера с Vision (меньше 21 байта) доходит до клиента сразу, а не застревает  
✅ xhttp packet-up: GOAWAY сервера на связи выгрузки переоткрывает связь, а не рвёт соединение клиента  
✅ Туннель: если данные узла не удалось доставить клиенту, соединение сбрасывается, а не закрывается как штатно завершённое — обрезанная загрузка не выдаётся за полную  
✅ Shadowsocks: под нагрузкой данные потока больше не теряются молча, а повтор при занятом сокете не уходит с чужим номером, который сервер не открывает; SOCKS5: ответ авторизации проверяется по своей версии, а метод «имя и пароль», которого клиент не предлагал, — отказ  
✅ hysteria2 с обфускацией Gecko: приём больше не портит память, а неверные размеры пакетов называются в причине, а не дают молча неработающий узел  
✅ Хаб xsteer: пакеты между клиентами хаба больше не портятся при сборке пачки  
✅ Мост Telegram: соединение из запаса, закрытое сервером, дозванивается заново, а не отдаётся клиенту мёртвым  
✅ Оборванный ядром Linux дамп netlink (конец дампа с кодом ошибки) больше не принимается за полный; дамп маршрутов и правил, прерванный их сменой, повторяется  
✅ Повисшая внешняя команда (`nft`, `ip`) снимается через минуту и не останавливает демон  
✅ На Linux 6.15 и новее сторож больше не заменяет таблицу без причины: число элементов наборов в сверку не входит  
✅ «|» в имени правила больше не портит таблицу резолвера; спеки с такими именами читаются как прежде  
✅ Резолвер: вопрос с байтом 0, точкой, пробелом или управляющим символом внутри метки имени больше не подменяет настоящий адрес под поддельным для всех клиентов, не отравляет кэш DNS и не дописывает строк в файл состояния fake-IP — такой вопрос уходит наверх как есть, без правил, кэша и fake-IP; строки файла состояния с такими именами, с поддельным адресом, уже выданным другому имени, или с подменой на адрес пула при загрузке отбрасываются, и файл переписывается без них  
✅ Тело подписки пишется с правами 0600, а не 0644  
✅ Поток соединений чужого процесса к управляющему сокету не останавливает демон и не забивает журнал: соединения принимаются пачками, тело отвергнутого не дочитывается, строк об отказах — не больше пяти в минуту  
✅ Прокси: датаграмма SOCKS5 UDP из трёх байт не читается за концом буфера; метка времени в ответе сервера ss2022 проверяется (не дальше 30 с от часов роутера)  
✅ xsteer: слепой обрыв сессии поддельным RST и повтор перехваченной записи после переупорядочивания больше не проходят  
✅ obfs: поддельный RST с угаданным портом больше не обрывает сессию; сервер не вытесняет живые сессии новыми SYN и держит больше 64 клиентов  

### 🔧 ИЗМЕНЕНО
▫️ Переход с 2.0.x: протоколы стали плагинами. `steer-core` 2.1.0 при установке снимает пакеты `steer-vless`, `-hysteria2`, `-proxy`, `-xsteer`, `-obfs`, `-warpbox`, `-tgws` и `steer-extended` (apk — `provides`/`replaces`, opkg — `Conflicts`), а `steer plugin migrate` ставит нужные плагины протоколов из семени в пакете ядра, без сети, по видам выходов спеки, и обновляет уже стоящие из семени; `kmod-tun` остаётся за ядром. Если стоит `steer-box-connector`, ядро ставится вместе с коннектором 2.1 одной командой  
▫️ Плагины ставятся только с подписью: открытые ключи официальных репозиториев приходят в пакете `steer-core` (`/usr/share/steer/keys`), чужой репозиторий добавляется со своим ключом (`steer plugin repo add <url> <номер ключа>`); плагин из файла без подписи ставится только с `--unsigned` и сам не обновляется; индекс репозитория больше 16 МиБ, подпись больше 1 МиБ и архив длиннее размера из подписанного индекса отвергаются  
▫️ Мост Telegram (`kind: tgws`) — плагин `tgws` из репозитория `splify2-extended-plugins`, в семени ядра его нет: правило перехвата ставит ядро по его шаблону, порт моста выдаётся постоянным ресурсом, пул доменов, пути дата-центров, адреса дата-центров и туннели WARP — настройки плагина во вкладке «Плагины»; настройка `pick` подбирает пути к дата-центрам в фоне раз в 6 ч без перезапуска моста; настройки микропакета `stgws` переносятся в плагин при установке; модуль `steer-tgws`, мини-сборка `stgws` и команда `tgws-instances` сняты; без плагина выход моста недоступен и живёт по своему `on_fail`, остальные правила работают, а `status` и `diag` называют плагин, который нужно поставить  
▫️ Выход `kind: zapret` удалён вместе с обработчиком `steer-nfqws` и командой `zapret-instances`: спека с ним отвергается с названием замены — модуль DPI recheck или `kind: direct`; `on_fail: zapret` (уживание с системным zapret) остался  
▫️ Раскладка набора правил для Linux 4.9 удалена: нужен nat в `inet` (Linux 5.2 и новее); из ядра steer убраны и прочие остатки совместимости — чтение форматов времён до 2.0.0, неиспользуемые функции и поля  
▫️ Проверка спеки строже: путь списка с «|», управляющим символом или началом `dns:`, адрес с ведущим нулём в октете (`010.1.1.1` nft читал восьмеричным, как `8.1.1.1`), `from` и `from_default` спеки v1 не адресом, порт спеки v1 вне диапазона, имя, начинающееся с «-», и имена «.» и «..» — отказ с названием места; строка списка с ведущим нулём в октете пропускается как испорченная  
▫️ Сторож больше не перезапускает туннель, через который идёт трафик, по одному проходу без ответа: приговор — после трёх проходов подряд (следующий через 15 с, около 45 с от первого молчания), туннель без ARP (WireGuard, TUN, PPP), который принимает трафик, не перезапускается вовсе, а при провале у провайдера (нет пути наружу у самого роутера) исправные туннели не трогаются — долгие соединения (голос, игры) не рвутся от потерянных пакетов проверки. Член группы, чья проверка молчит, не теряет установленные соединения, пока молчание не подтверждено, а новые группа сразу ведёт через живого члена. Проверка по ICMP шлёт до трёх эхо-запросов на адрес вместо одного  
▫️ Группы с `order` и `latency` закрепляют соединение за выбранным членом: смена члена по задержке и возврат на предпочтительный не рвут установленные соединения — они доживают на прежнем члене, пока тот жив, а новые идут на выбранный; у `manual` и у пула `devices` спеки v1 закрепления нет  
▫️ Подъём выхода и замена узла пробуют кандидатов наперегонки (следующий — через 250 мс, не больше 8 сразу), а не по одному с ожиданием каждого — выход с мёртвыми узлами в подписке поднимается быстрее  
▫️ Подмену адреса IPv4 (masquerade) для выходов `interface`, `awg` и членов WARP ставит само ядро steer в своей таблице — в зоне fw4 она больше не нужна  
▫️ fake-IP: настоящий адрес под поддельным не меняется, пока имя спрашивают, даже если в свежем ответе DNS его нет, — сеансы QUIC после паузы не уходят на другой сервер; адрес заменяется, когда имя спросили после десяти минут простоя или прежнего адреса нет в ответах полчаса  
▫️ fake-IP: на имя, которое сервер DNS блокирует ответом `0.0.0.0` или `::`, клиент получает пустой адрес и отказ сразу, а не поддельный адрес с ожиданием до срока соединения  
▫️ fake-IP: при исчерпанном пуле имя под правилом получает SERVFAIL, а не настоящий адрес мимо выхода; за одним клиентом (адрес IPv4 или префикс /64 IPv6, кроме петли) не больше 16384 поддельных адресов — у предела сначала возвращаются его же простоявшие имена, а если нечего, SERVFAIL получает только он  
▫️ Резолвер: у одного клиента не больше 128 из 1024 мест таблицы ожиданий — клиент, засыпающий резолвер вопросами без ответа, больше не отнимает DNS у остальных, его новый вопрос вытесняет его же самый давний  
▫️ Туннели: у одного клиента не больше четверти ожидающих рукопожатия, TCP открывается раньше UDP, сверх предела — `RST` для TCP и ICMP «порт недоступен» для UDP; поток датаграмм одного клиента на тысячи адресов больше не останавливает новые соединения остальных; поток UDP без единого ответа узла закрывается после 30 с тишины, а не 120 с  
▫️ Туннели: у памяти есть бюджет (половина доступной памяти, `STEER_TUN_MEM_MB`) — сотни медленных скачиваний одного клиента не доводят роутер до нехватки памяти; на пределе новые соединения получают отказ, а медленные читатели ждут  
▫️ Туннели: рукопожатие с узлом целиком укладывается в 16 с — сервер, отдающий ответ по байту, не держит соединения бесконечно  
▫️ Подписка: ответ панели без единого узла не заменяет рабочую подписку — `sub-fetch` отказывает с «прежняя подписка оставлена»; подписка больше 64 МиБ, скачанная или после распаковки gzip, отвергается с этим числом  
▫️ Идентификатор и модель устройства уходят только панели: хост, на который она переадресует (другой хост, порт или схема, кроме перехода того же хоста на https), их не получает  
▫️ Набор `.srs` с правилом, дерево которого больше 131072 узлов, отвергается с этим числом, а не занимает гигабайт памяти  
▫️ Сняты прочие искусственные пределы: вывод `conns` и ответы управляющего сокета (2000 записей, 1 МиБ), журнал `dns-log`, копии правила, зоны fw4, правила и источники наборов `.srs`, клиенты TCP резолвера, число адресов в ответе DNS (32 A и 16 AAAA), сессии хаба xsteer (128)  
▫️ Туннели используют несколько рабочих потоков по числу ядер и раздают пакеты без замков — выше скорость на многоядерных роутерах  
▫️ TCP клиентов в туннеле принимает TCP-стек ядра Linux (перенаправление nftables), собственный TCP-стек туннеля удалён  
▫️ xhttp packet-up: POST-запрос — до лимита узла `scMaxEachPostBytes`, а не около 16 КБ, размер каждого запроса случайный  
▫️ Туннель отдаёт клиенту большие записи (до 64 КБ вместо 8–9 КБ) — меньше накладных расходов  
▫️ hysteria2: UDP отправляется и принимается пачками — примерно вдвое меньше нагрузки на процессор  
▫️ steerd собирается с `-O2`  
▫️ Файл состояния fake-IP пишется в фоне через секунду после изменения, а не раз в минуту  
▫️ Спека v1 читается и переводится в v2 при загрузке; её ответы на AAAA теперь те же, что у v2  
▫️ Режим `realip` остаётся полноценным: предупреждение о его уходе убрано  
▫️ Круг `steer failover --loop` убран: выходы сторожит демон с `--watch`  
▫️ Ошибка YAML в спеке указывает на начало конструкции, где она случилась  
▫️ Оставшиеся английские сообщения журнала переведены  

### ✨ НОВОЕ
✅ Менеджер плагинов: `steer plugin` ставит, обновляет, снимает, включает и выключает плагины из подписанных репозиториев, без сети — из семени; те же действия — командами сокета `plugin-*`. Плагину с выбором системных пакетов (`awg`: `kmod-amneziawg` или `kmod-wireguard`) ставится первый, что есть в фидах, а отказ называет все пробованные  
✅ Плагины обновляются в фоне: раз в сутки, установка в ночном окне (по умолчанию 03:00–05:00), при неудаче проверки здоровья — откат на прежнюю версию  
✅ `steer spec-schema [--json]` — схема всей спеки v2: ключи, типы, значения, умолчания, подсказки, ссылки на имена и ключи каждого вида выхода; виды установленных плагинов вливаются с пометкой плагина  
✅ Отказы спеки, менеджера плагинов и управляющего сокета несут код и подстановки (`code`, `args`, список — в `docs/errors.md`) рядом с текстом  
✅ `steer version --json` называет версии ядра, steer-api и steer-abi  
✅ IPv6 через туннели (VLESS, hysteria2, прокси): TCP и UDP клиентов по IPv6 идут через выход, правила с `family: 6` и `both` ведут в него оба семейства; `ipv6: off` у выхода это отключает  
✅ IPv6 у узлов: подключения TCP и UDP по IPv6, в ссылках и выводе адрес в квадратных скобках  
✅ Семейство IP по правилам: `family: 4 | 6 | both` и `on_family_unavailable: block | fallback` — IPv6 без утечек, управление по сервисам  
✅ Плагин WARP (`warpbox`) и вид `kind: warp` в спеке v2 — группа WARP-туннелей: регистрация, подбор точек и сторож туннелей; регистрации и файлы туннелей (`/etc/steer/warp`) переживают обновление прошивки с сохранением настроек  
✅ WARP по умолчанию — один туннель, который на ходу переходит на самую быструю точку; без `countries` и `exclude_countries` берутся точки любых стран  
✅ Члены WARP: быстрый отказ, транспорт MASQUE (`transport: masque`) и IPv6, по умолчанию через NAT  
✅ Пул подписки: режим `pick: latency` берёт самые быстрые узлы в одно устройство и оценивает узел по трём пробам — задержка, разброс и потери  
✅ Выбор по стране: `only` берёт узлы только указанных стран, вместе с `pick: latency` и `exclude` — «самый быстрый, кроме страны X»; то же у групп выходов по стране живого узла члена  
✅ Страна выхода туннеля: заявленная по имени узла и фактическая по проверке через выход, расхождение помечается  
✅ Торренты мимо VPN: ключ `torrent: block | direct` у правила — BitTorrent клиентов (всё, что Xray и sing-box на сервере назовут bittorrent, плюс DHT и трекеры) не уходит в выход правила: отказ или напрямую; `status` считает отвергнутое и пущенное напрямую  
✅ Выход `kind: block` — «Блок» в выводе: отказ (RST, ICMP) доходит до клиента сразу, и он не ждёт срока  
✅ Выключение QUIC по правилу: `quic: block` отвергает UDP/443 к назначениям правила, и браузер переходит на TCP  
✅ DNS-over-HTTP/3: апстрим `h3://имя[:порт][/путь]` в резолвере; соединение держится с PING, как у DNS по QUIC  
✅ DoT и DoH: ClientHello можно делить на две записи TLS (ключ `fragment` у апстрима)  
✅ `dns.mesh_clients: true` заворачивает запросы DNS клиентов Tailscale и ZeroTier на резолвер steer — доменные правила действуют и на них (по умолчанию выключено)  
✅ `steer dns-probe` проверяет DNS-серверы через апстримы резолвера  
✅ `status` показывает состояние WARP-туннелей, колонию и страну живого туннеля, а также поддержку деления ClientHello и DoH3  
✅ `steer spec convert --json` выводит спеку v2 JSON-объектом  
✅ xsteer: пачки кадров получает только сторона, которая умеет их собирать; прежние клиенты и хабы работают как раньше  
✅ Пакеты для архитектуры `aarch64_cortex-a73` (например, Xiaomi BE7000)  


## Установка

Ядро маршрутизации по политикам для OpenWrt.

**Какой пакет брать.** Пакет один — `steer-core-*` с архитектурой в имени (та же, что показывает
`apk --print-arch` на роутере): ядро, библиотеки, менеджер плагинов, ключи официального
репозитория и семя — подписанные плагины протоколов под эту архитектуру. Протоколы (vless,
hysteria2, trojan/shadowsocks/socks/http/vmess, xsteer, obfs, WARP) — плагины `.s2p` официального
репозитория splify2: при установке ядро ставит их само из сети, а без сети — из семени. Прежние
пакеты `steer-vless`, `steer-hysteria2`, `steer-proxy`, `steer-xsteer`, `steer-obfs`,
`steer-tgws`, `steer-warpbox` и `steer-extended` пакет ядра заменяет и снимает в той же
транзакции, а выходы, которые на них стояли, получают плагины.

sing-box для podkop и forkop — плагин `box-connector` и пакет-заглушка `steer-box-connector`
из выпусков [steer-box-connector](https://github.com/splify2/steer-box-connector/releases).

**Два формата.** `.apk` — для OpenWrt 25.12 и новее, `.ipk` — для 24.10, 23.05
и всего, что осталось на opkg. Содержимое одинаковое, отличаются только
метаданные пакета.

```sh
# OpenWrt 25.12+
apk add --allow-untrusted ./steer-core-2.1.0-1_<arch>.apk
# OpenWrt 24.10 и старше
opkg install ./steer-core_2.1.0-1_<arch>.ipk
```

**`steer-obfs-*.tar.gz` — серверная половина обфускации, для VPS.** Нужна
только выходу с `obfs`: она принимает поддельный TCP снаружи и отдаёт
датаграммы локальному WireGuard. Компилятор на сервере не нужен: бинарник в
архиве статический — программа плагина `obfs`, та же, что на роутере.

```sh
tar xzf steer-obfs-2.1.0-x86_64.tar.gz
cd obfs-x86_64 && sudo sh install.sh --port 4567 --forward 127.0.0.1:51820
```

**`steer-hub-*.tar.gz` — хаб звезды xsteer, для VPS.** Отдельная половина от
obfs: здесь свой протокол (поддельный TCP с обликом TLS) и своя подкоманда
`xsteer-hub`, которой в сборке для роутера нет. Имя архива без версии —
установщик тянет его по фиксированному пути. Внутри бинарник, установщик и
справка; распаковал и запустил, ключи хаб делает сам.

```sh
tar xzf steer-hub-x86_64.tar.gz && sudo sh xs_install.sh
```
