## Что нового в 2.1.0

🛠 **steer 2.1.0** — новый модуль WARP, выбор самых быстрых узлов, быстрее туннели и исправления DNS и маршрутизации 👇

### 🐞 ИСПРАВЛЕНИЯ
✅ Собственный трафик steer больше не проходит через общий zapret  
✅ Замеры туннелей и over больше не теряются на локальном интерфейсе  
✅ Блокировка `block` действует только в исходном направлении трафика  
✅ Снятие правил удаляет только правила своей пары метки и таблицы  
✅ Проверка здоровья выхода по TCP идёт через его метку, а не через TUN  
✅ Туннели берут настоящий адрес fake-IP из ядра, а не только из файла  
✅ hysteria2 в режиме Brutal: лимит отправки делится между соединениями, а не применяется к каждому отдельно  
✅ Группы DNS-серверов в режиме race: при отказе серверов группа уходит на паузу, а поздний ответ больше не снимает отказ  
✅ Группа WARP при старте не делает ложной замены точки  
✅ xhttp packet-up: POST-запросы не превышают лимит узла `scMaxEachPostBytes`, размер каждого запроса случайный  
✅ `rm-file` работает и тогда, когда спека записана в YAML  
✅ TCP-стек: сегменты, пришедшие не по порядку, корректно ждут закрытия дыры  
✅ Список JSON без закрывающей скобки теперь даёт ошибку, а не молча продолжает разбор  
✅ DNS-over-HTTP/3 к Cloudflare работает: запрос без `content-length` больше не получает ответы 405 и 400  
✅ Замер групп по `https://` к Google и Cloudflare исправлен  
✅ Shadowsocks и VMess: расшифрованные данные при нехватке места в буфере не обрывают соединение  
✅ На 32-битном MIPS исправлены ChaCha20-Poly1305, а на big-endian MIPS — хеши и AES-GCM  
✅ Размер стека потоков учитывает статическую TLS-память glibc  
✅ DNS-демон не падает, когда не хватает памяти для набора правил  

### 🔧 ИЗМЕНЕНО
▫️ TCP-трафик клиентов идёт только через ядро steer, собственный TCP-стек туннеля удалён  
▫️ Группы с `order` и `latency` закрепляют соединение за выбранным узлом  
▫️ Туннели используют несколько рабочих потоков по числу ядер и раздают пакеты без замков — выше скорость на многоядерных роутерах  
▫️ Туннель отдаёт клиенту большие записи (до 64 КБ вместо 8–9 КБ) — меньше накладных расходов  
▫️ hysteria2: UDP отправляется и принимается пачками — примерно вдвое меньше нагрузки на процессор  
▫️ TLS: чтение не запрашивает готовность сокета перед каждым чтением — меньше системных вызовов  
▫️ Допуск группы `warp` по умолчанию 50 мс (было 200 мс)  
▫️ fake-vless: очередь входящих соединений 512 (было 5)  
▫️ Выход `kind: block` в выводе отображается как «Блок»  
▫️ Ключи и секреты протоколов стираются из памяти надёжно, без риска, что компилятор уберёт эту очистку  
▫️ В документации: что делать, если после оборванной установки apk пишет «breaks: world»  

### ✨ НОВОЕ
✅ Модуль WARP: регистрация, подбор точек и сторож туннелей  
✅ В спеке v2 появился вид `kind: warp` — группа WARP-туннелей  
✅ WARP по умолчанию — один туннель, который на ходу переходит на самую быструю точку  
✅ Без `countries` и `exclude_countries` WARP берёт точки любых стран

✅ У членов WARP есть IPv6, по умолчанию через NAT  
✅ Пул подписки: режим `pick: latency` берёт самые быстрые узлы в одно устройство  
✅ IPv6 у узлов и подключений к ним: TCP и UDP по IPv6, в ссылках и выводе адрес в квадратных скобках  
✅ DNS-over-HTTP/3: апстрим `h3://имя[:порт][/путь]` в резолвере  
✅ DoT и DoH: ClientHello можно делить на две записи TLS (ключ `fragment` у апстрима)  
✅ `steer dns-probe` проверяет DNS-серверы через апстримы резолвера  
✅ `steer spec convert --json` выводит спеку v2 JSON-объектом  
✅ `status` показывает состояние WARP-туннелей, а также колонию и страну живого туннеля  
✅ `status` показывает, поддерживаются ли деление ClientHello и DoH3


## Установка

Ядро маршрутизации по политикам для OpenWrt.

**Какой пакет брать.** Имя файла содержит архитектуру — ту же, что показывает
`apk --print-arch` на роутере.

* `steer-core-*` — ядро: каналы, наборы адресов, доменные списки с fake-IP, failover
  между устройствами, общая криптография (библиотеки `libsteer` и `libsteer-wolfssl`
  лежат внутри пакета). Заменяет прежние пакеты `steer`, `libsteer` и `libsteer-wolfssl`.
* `steer-vless-*`, `steer-xsteer-*` — клиенты туннелей (VLESS/Reality с Vision,
  транспортами tcp/grpc/xhttp/ws/httpupgrade; звезда xsteer) — отдельные модули.
  Нужны, только если туннель поднимает само ядро; для готового wireguard или
  amneziawg достаточно ядра.
* `steer-obfs-*` (обфускатор WireGuard), `steer-tgws-*` (мост Telegram) и
  `steer-hysteria2-*` (клиент hysteria2) — модули.
* `steer-extended-*` — мета-пакет для перехода с 1.x: ядро и модули vless, xsteer, obfs,
  tgws (без hysteria2 и proxy). Новой установке не нужен; при обновлении роутера с 1.x
  ставьте его вместе с ядром и модулями (команда ниже берёт все пакеты разом) — тогда
  apk не упрётся в конфликт с прежним steer-extended, а opkg не оставит его запись.
  После перехода его можно снять: ядро и модули останутся.

Модуль должен быть той же версии, что ядро (менеджер пакетов следит сам).

**Два формата.** `.apk` — для OpenWrt 25.12 и новее, `.ipk` — для 24.10, 23.05
и всего, что осталось на opkg. Содержимое одинаковое, отличаются только
метаданные пакета.

```sh
# OpenWrt 25.12+ (все пакеты нужной архитектуры разом)
apk add --allow-untrusted ./*-2.1.0-1_<arch>.apk
# OpenWrt 24.10 и старше
opkg install ./*-2.1.0-1_<arch>.ipk
```

**`steer-obfs-*.tar.gz` — серверная половина обфускации, для VPS.** Нужна
только выходу с `obfs`: она принимает поддельный TCP снаружи и отдаёт
датаграммы локальному WireGuard. Компилятор на сервере не нужен: бинарник в
архиве статический, код обфускации в нём тот же, что в модуле `steer-obfs`.

```sh
tar xzf steer-obfs-2.1.0-x86_64.tar.gz
cd obfs-x86_64 && sudo sh install.sh --port 4567 --forward 127.0.0.1:51820
```

**`steer-hub-*.tar.gz` — хаб звезды xsteer, для VPS.** Отдельная половина от
obfs: здесь свой протокол (поддельный TCP с обликом TLS) и своя подкоманда
`xsteer-hub`, которой в сборке для роутера нет. Имя архива без версии —
установщик тянет его по фиксированному пути. Внутри бинарник, установщик и
справка; распаковал и запустил, ключи хаб делает сам.

```sh
tar xzf steer-hub-x86_64.tar.gz && sudo sh xs_install.sh
```
