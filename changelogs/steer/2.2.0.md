## Что нового в 2.2.0

- На 32-битных системах время супервизора, таймеров и их потребителей хранится в 64 битах: helpers продолжают запускаться после 24,9 суток работы роутера.
- Таймер, немедленно перезапускающий себя, больше не задерживает обработку сокетов и сигналов.
- Помощник расширения встроенного вида получает файл своей конфигурации; обновление параметров перезапускает его с актуальным файлом.
- Исправлена импортная libc Zig 0.13 для динамических 32-битных сборок musl (символы time64).
- Vision переключается в DIRECT после полного получения данных и padding кадра, включая фрагментированные ответы.
- DNS применяет новую таблицу вместе со списками правил только после успешного разбора и загрузки; при ошибке сохраняется предыдущая конфигурация. Недописанная таблица сбрасывается при смене трубы демона.
- TLS 1.3 обрабатывает KeyUpdate и проверяет порядок сообщений рукопожатия; HTTP/2 разбирает фрагментированные заголовки и статус gRPC. Старые размеры структур net1 сохранены.
- Hysteria2 принимает ответ потока вместе с крупной порцией данных; сборка UDP ограничена по числу, памяти и времени жизни. QUIC отвергает устаревший поток без обрыва соседних и учитывает длину CID сервера в пределе датаграммы.
- Добавлена пакетная архитектура arm_cortex-a7; soft-float сборки arm_cortex-a7 и arm_cortex-a9 явно отключают FP/NEON.
- После перезапуска DNS сохранённый backend без времени наблюдения не считается свежим. Поздний ответ старого upstream не попадает в кэш новой конфигурации.
- Демон получает подтверждения применения DNS-таблиц; отвергнутая таблица допускает повтор, при заполнении окна сохраняется последнее отложенное обновление.
- Проба VLESS дочитывает фрагментированный заголовок ответа в пределах общего срока.
- Ошибка перестроения реестра плагинов сохраняет предыдущий реестр. Ошибки индекса формируются до освобождения его данных.
- Прерванная установка простого одиночного плагина восстанавливается по журналу; если восстановление не поддерживается, менеджер возвращает явный отказ и сохраняет журнал.
- Check и plan не записывают реестр меток. Apply проверяет обязательные правила IPv4/IPv6 и blackhole IPv4; неудачный переход сторожа публикуется только после подтверждённого повтора.
- `srs-read` сохраняет прежние выходные файлы при ошибке чтения/записи. `fit` не выдаёт успешный результат при ошибке записи исключений и правильно считает прирост покрытия IPv4.
- Ось совместимости общих криптобиблиотек обновлена до `steer-crypto 2.0`; поставляются net1 1.5.1 и соответствующие плагины.


## Установка

Ядро маршрутизации по политикам для OpenWrt.

**Какой пакет брать.** Пакет один — `steer-core-*` с архитектурой в имени (та же, что показывает
`apk --print-arch` на роутере): ядро, библиотеки, менеджер плагинов, ключи официального
репозитория и семя — подписанные плагины протоколов под эту архитектуру. Протоколы (vless,
hysteria2, trojan/shadowsocks/socks/http/vmess, xsteer, obfs, WARP) — плагины `.s2p` официального
репозитория splify2: при установке ядро ставит их само из сети, а без сети — из семени. Прежние
пакеты `steer-vless`, `steer-hysteria2`, `steer-proxy`, `steer-xsteer`, `steer-obfs`,
`steer-tgws`, `steer-warpbox` и `steer-extended` пакет ядра заменяет и снимает в той же
транзакции, а выходы, которые на них стояли, получают плагины.

sing-box для podkop и forkop — плагин `box-connector` и пакет-заглушка `steer-box-connector`
из выпусков [steer-box-connector](https://github.com/splify2/steer-box-connector/releases).

**Два формата.** `.apk` — для OpenWrt 25.12 и новее, `.ipk` — для 24.10, 23.05
и всего, что осталось на opkg. Содержимое одинаковое, отличаются только
метаданные пакета.

```sh
# OpenWrt 25.12+
apk add --allow-untrusted ./steer-core-2.2.0-1_<arch>.apk
# OpenWrt 24.10 и старше
opkg install ./steer-core_2.2.0-1_<arch>.ipk
```

**`steer-obfs-*.tar.gz` — серверная половина обфускации, для VPS.** Нужна
только выходу с `obfs`: она принимает поддельный TCP снаружи и отдаёт
датаграммы локальному WireGuard. Компилятор на сервере не нужен: бинарник в
архиве статический — программа плагина `obfs`, та же, что на роутере.

```sh
tar xzf steer-obfs-2.2.0-x86_64.tar.gz
cd obfs-x86_64 && sudo sh install.sh --port 4567 --forward 127.0.0.1:51820
```

**`steer-hub-*.tar.gz` — хаб звезды xsteer, для VPS.** Отдельная половина от
obfs: здесь свой протокол (поддельный TCP с обликом TLS) и своя подкоманда
`xsteer-hub`, которой в сборке для роутера нет. Имя архива без версии —
установщик тянет его по фиксированному пути. Внутри бинарник, установщик и
справка; распаковал и запустил, ключи хаб делает сам.

```sh
tar xzf steer-hub-x86_64.tar.gz && sudo sh xs_install.sh
```
