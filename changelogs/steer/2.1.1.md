## Что нового в 2.1.1

🛠 **steer 2.1.1** — туннели больше не забирают память роутера 👇

### 🐞 ИСПРАВЛЕНИЯ
✅ Каждый туннель VLESS, hysteria2, прокси и xsteer держал около 25 МБ памяти ядра Linux, пока был поднят: у устройства туннеля с несколькими очередями система заводила свою очередь передачи на каждую из 256, размером под запас на пики. На роутере с 256 МБ два-три туннеля занимали треть памяти, интерфейс и обновления начинали отказывать. Теперь устройство туннеля идёт без этих очередей (noqueue); запас на пики остался в самом устройстве. Исправление — в плагине `net1` 1.4.1: роутер с 2.1.0 получит его автообновлением плагинов, с пакетом 2.1.1 оно ставится сразу  


## Установка

Ядро маршрутизации по политикам для OpenWrt.

**Какой пакет брать.** Пакет один — `steer-core-*` с архитектурой в имени (та же, что показывает
`apk --print-arch` на роутере): ядро, библиотеки, менеджер плагинов, ключи официального
репозитория и семя — подписанные плагины протоколов под эту архитектуру. Протоколы (vless,
hysteria2, trojan/shadowsocks/socks/http/vmess, xsteer, obfs, WARP) — плагины `.s2p` официального
репозитория splify2: при установке ядро ставит их само из сети, а без сети — из семени. Прежние
пакеты `steer-vless`, `steer-hysteria2`, `steer-proxy`, `steer-xsteer`, `steer-obfs`,
`steer-tgws`, `steer-warpbox` и `steer-extended` пакет ядра заменяет и снимает в той же
транзакции, а выходы, которые на них стояли, получают плагины.

sing-box для podkop и forkop — плагин `box-connector` и пакет-заглушка `steer-box-connector`
из выпусков [steer-box-connector](https://github.com/splify2/steer-box-connector/releases).

**Два формата.** `.apk` — для OpenWrt 25.12 и новее, `.ipk` — для 24.10, 23.05
и всего, что осталось на opkg. Содержимое одинаковое, отличаются только
метаданные пакета.

```sh
# OpenWrt 25.12+
apk add --allow-untrusted ./steer-core-2.1.1-1_<arch>.apk
# OpenWrt 24.10 и старше
opkg install ./steer-core_2.1.1-1_<arch>.ipk
```

**`steer-obfs-*.tar.gz` — серверная половина обфускации, для VPS.** Нужна
только выходу с `obfs`: она принимает поддельный TCP снаружи и отдаёт
датаграммы локальному WireGuard. Компилятор на сервере не нужен: бинарник в
архиве статический — программа плагина `obfs`, та же, что на роутере.

```sh
tar xzf steer-obfs-2.1.1-x86_64.tar.gz
cd obfs-x86_64 && sudo sh install.sh --port 4567 --forward 127.0.0.1:51820
```

**`steer-hub-*.tar.gz` — хаб звезды xsteer, для VPS.** Отдельная половина от
obfs: здесь свой протокол (поддельный TCP с обликом TLS) и своя подкоманда
`xsteer-hub`, которой в сборке для роутера нет. Имя архива без версии —
установщик тянет его по фиксированному пути. Внутри бинарник, установщик и
справка; распаковал и запустил, ключи хаб делает сам.

```sh
tar xzf steer-hub-x86_64.tar.gz && sudo sh xs_install.sh
```
