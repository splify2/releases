## Что нового в 2.0.4

🛠 **steer 2.0.4** — исправления по обращениям из чата splify2 и steer#6, ускорение туннелей 👇

### 🐞 ИСПРАВЛЕНИЯ
✅ VLESS: после нескольких проверок узла он больше не начинает молчать на ClientHello — одна проверка открывала к узлу до пяти соединений сразу, и сервер или провайдер начинал их резать. Запасные соединения теперь заводятся, только когда через выход действительно идёт поток, а после отказа узла пауза растёт с 5 до 60 секунд  
✅ VLESS Reality и TLS: если узел не ответил на длинный ClientHello (с постквантовым обменом ключами), ядро сразу пробует короткий и запоминает узел на час  
✅ Выход из смешанной подписки (vless + hysteria2): узел, который отвечает на проверку, но не держит соединения, считается мёртвым — выход переходит на другой протокол  
✅ Возврат на оживший узел — не дольше 30 секунд, а не через 5 минут  
✅ hysteria2: одна большая UDP-датаграмма больше не останавливает туннель целиком  
✅ UDP больше 4 КБ проходит через VLESS и hysteria2 (крупные ответы DNS, игры, звонки); фрагменты собираются в любом порядке, первая крупная датаграмма нового соединения не теряется  
✅ Выгрузка изредка стояла больше 10 секунд в начале соединения — исправлено  
✅ Подписки: значки в именах узлов (⚡ ⭐ 📱) больше не превращаются в «u26a1»; ссылки с `type=raw` больше не отбрасываются; узел с Vision поверх gRPC или xhttp пропускается с понятной причиной, а не перезапускает выход без конца  
✅ Пул узлов: при «работают сразу» больше 64 соединения раздаются на все узлы  
✅ Смена выхода у правила при очень больших списках больше не подвешивает ядро на секунды

### 🔧 ИЗМЕНЕНО
▫️ Выгрузка через gRPC и xhttp больше не упирается в окно узла (по замеру автора правки — в разы быстрее), а скачивание рядом с выгрузкой больше не проседает; xhttp packet-up — в несколько раз быстрее. Правки стека TUN и xhttp перенесены из [hoaxisr/tunvless](https://github.com/hoaxisr/tunvless) — спасибо hoaxisr  
▫️ xhttp: настройки по Xray 26.3 — выгрузка по второй связи снова работает  
▫️ Соединения, где первым говорит сервер (SSH, почта), больше не зависают через туннель


## Установка

Ядро маршрутизации по политикам для OpenWrt.

**Какой пакет брать.** Имя файла содержит архитектуру — ту же, что показывает
`apk --print-arch` на роутере.

* `steer-core-*` — ядро: каналы, наборы адресов, доменные списки с fake-IP, failover
  между устройствами, общая криптография (библиотеки `libsteer` и `libsteer-wolfssl`
  лежат внутри пакета). Заменяет прежние пакеты `steer`, `libsteer` и `libsteer-wolfssl`.
* `steer-vless-*`, `steer-xsteer-*` — клиенты туннелей (VLESS/Reality с Vision,
  транспортами tcp/grpc/xhttp/ws/httpupgrade; звезда xsteer) — отдельные модули.
  Нужны, только если туннель поднимает само ядро; для готового wireguard или
  amneziawg достаточно ядра.
* `steer-obfs-*` (обфускатор WireGuard), `steer-tgws-*` (мост Telegram) и
  `steer-hysteria2-*` (клиент hysteria2) — модули.
* `steer-extended-*` — мета-пакет для перехода с 1.x: ядро и модули vless, xsteer, obfs,
  tgws (без hysteria2 и proxy). Новой установке не нужен; при обновлении роутера с 1.x
  ставьте его вместе с ядром и модулями (команда ниже берёт все пакеты разом) — тогда
  apk не упрётся в конфликт с прежним steer-extended, а opkg не оставит его запись.
  После перехода его можно снять: ядро и модули останутся.

Модуль должен быть той же версии, что ядро (менеджер пакетов следит сам).

**Два формата.** `.apk` — для OpenWrt 25.12 и новее, `.ipk` — для 24.10, 23.05
и всего, что осталось на opkg. Содержимое одинаковое, отличаются только
метаданные пакета.

```sh
# OpenWrt 25.12+ (все пакеты нужной архитектуры разом)
apk add --allow-untrusted ./*-2.0.4-1_<arch>.apk
# OpenWrt 24.10 и старше
opkg install ./*-2.0.4-1_<arch>.ipk
```

**`steer-obfs-*.tar.gz` — серверная половина обфускации, для VPS.** Нужна
только выходу с `obfs`: она принимает поддельный TCP снаружи и отдаёт
датаграммы локальному WireGuard. Компилятор на сервере не нужен: бинарник в
архиве статический, код обфускации в нём тот же, что в модуле `steer-obfs`.

```sh
tar xzf steer-obfs-2.0.4-x86_64.tar.gz
cd obfs-x86_64 && sudo sh install.sh --port 4567 --forward 127.0.0.1:51820
```

**`steer-hub-*.tar.gz` — хаб звезды xsteer, для VPS.** Отдельная половина от
obfs: здесь свой протокол (поддельный TCP с обликом TLS) и своя подкоманда
`xsteer-hub`, которой в сборке для роутера нет. Имя архива без версии —
установщик тянет его по фиксированному пути. Внутри бинарник, установщик и
справка; распаковал и запустил, ключи хаб делает сам.

```sh
tar xzf steer-hub-x86_64.tar.gz && sudo sh xs_install.sh
```
